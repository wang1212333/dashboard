# 实时看板分享到飞书

入口：我的看板 → 更多操作 → 分享 → 发送到飞书 → 搜索并选择同事 → 预览 → 发送卡片。

发送的是飞书机器人卡片，按钮打开实时网页；卡片消息本身不持续更新业务数值。服务不会因发布或生成链接自动发消息。

## 链接选择

- 已核验部署的同一发布版本：优先使用服务器地址。当前已登记 `dsh-realtime-acceptance / rev-0006`。分享人电脑关闭后页面仍能查询，但接收人需要已有 Jupyter 权限。卡片不宣称免登录、不设置虚构有效期。
- 其他已发布实时版本：生成 1/7/30 天内网链接，再发送卡片。卡片明确本机必须保持运行，过期或撤销后拒绝访问。
- 静态看板：沿用原来的静态快照卡片。

服务器发布登记保存于用户目录 `.config/dsh-workbench/server-publications.json`，也可由 `DSH_SERVER_PUBLICATIONS_FILE` 指定。登记包含资产、版本、部署 URL、原始发布 HTML 的 SHA-256 和验证时间；不包含凭据。只有当前已发布版本与摘要同时匹配才使用服务器链接。新版本不会自动冒用旧部署地址。

## 发送校验与可靠性

DSH 从资料库读取标题和发布版本。内网实时链接必须属于当前资产、当前发布版本，管理 ID、地址和令牌校验全部通过；撤销链接不能发送。服务器模式从服务端登记读取 URL，不采信浏览器传入地址。

已有分享服务增加 `/api/feishu/send-live`，要求原管理认证。前端只调用 DSH 同源接口，不持有发布密钥。复用原应用身份、通讯录搜索、发送记录和幂等请求编号；相同请求不会重复发送。`preview:true` 只返回卡片，不调用发送接口。

## 当前范围

飞书发送由本机现有应用机器人完成；卡片成功发送后，服务器版看板访问不依赖本机。当前未实现服务器计划推送、DSH 自动上传全部新发布版本、普通同事免 Jupyter 权限的独立访问入口。

## 验证

新增 DSH 测试覆盖发布摘要匹配、实时链接归属、撤销、地址约束及前端脚本编译。分享服务测试覆盖管理认证、服务器/内网文案、过期链接、非 HTTP 地址拒绝及预览不发送；已有静态分享和飞书幂等测试通过。

实际工作台已验证服务器链接优先、飞书配置读取、实时卡片预览，以及用户/机器人身份有效。真实消息发送与收信结果单独记录在 `deliverables/live-feishu-evidence.json`，不能把预览通过等同于收信通过。

## 通用服务器部署（2026-09-14）
实时看板分享窗口现可直接部署任意已发布版本。完成现有 Jupyter 登录后，服务器真实查询校验、固定版本发布和签名回执登记自动完成；卡片自动使用该版本服务器链接。详见 deploy/live-server/README.md。原单看板人工登记已被通用流程替代。静态看板仍走快照分享。


### 发布即部署修正
点击实时看板的发布按钮会自动继续服务器部署；仅服务器签名回执核验后界面才显示发布完成。未部署的本机版本标记为待完成服务器发布，可原按钮重试。已部署版本从列表打开时使用服务器链接。
