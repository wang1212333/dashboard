# 分享弹窗优化交付（2026-09-14）

## 范围与复用

在现有 `dashboardSharingBehavior()` 中替换原弹窗，不增加第二个分享组件。入口事件仍为 `dsh:share-dashboard`。样式独立到 `dashboard-sharing-styles.ts`；图标复用官方 Tabler（MIT），Tooltip 复用工作台 `data-tooltip`。

原有混排的链接维护与飞书表单，调整为：读取上下文及已有链接 → 复用或生成 → 复制，或展开飞书发送。飞书默认折叠，生成不复制、不发送。管理列表改为弹窗内部视图，返回保留输入。

复用 `/dashboards/:id/shares` GET/POST/DELETE、`/feishu` 的配置/搜索/发送、`window.dshDeployReleased` 部署与回执、服务端 `serverPublication` 精确版本校验、`feishu.send` 幂等记录和飞书 uuid。没有修改看板查询、权限或消息卡片格式。

最小后端补充：原 `preview` action 增加只读快照支持，仍调用 `dashboardCard`；实时卡片仍调用 `liveDashboardCard`。预览只返回原卡片、不调用发送。发送和预览均校验版本及链接有效性；服务器链接变更时拒绝旧 URL。

## 状态与保护

- 初始化 loading、空列表和查询失败分别呈现；未知查询模式不标为快照。
- 多候选由用户选择，不随意取第一条；生成与发送均单飞；关闭/换链接后的旧异步结果被忽略。
- 发送前重新读取链接并预检；发送中固定完整快照；失败保留接收人、附言、链接和同一请求编号。重试前校验失败也不丢弃旧编号。
- 不确定生成结果先查询，仍无法确认时要求用户核查并显式确认，不盲目重建。
- 成功展示实际接收人；继续分享复用链接并清空下一次接收人与附言。
- Esc / 遮罩关闭、焦点限制与恢复、背景滚动恢复；只有一个弹窗滚动区域。

## 实测

- `npm run build` 通过。
- 37 项 Vitest 工作台/分享回归通过（其中 9 项执行真实分享控制器、仅替换 DOM 渲染）。最后文案调整后 15 项分享相关测试再次通过。
- 7 项在线分享服务测试通过，覆盖鉴权、撤销、到期、持久化幂等、实时及快照真实卡片预览不发送。
- 内置浏览器：生成→复制反馈→关闭再打开复用；单人确认与同名部门区分；附言、真实卡片预览；管理返回保留输入；成功→继续分享→完成；失败→同编号重试；列表失败→重试；375px 无抽屉内横向溢出，Tab/Shift+Tab 循环，Esc 返回入口并解除滚动锁定。
- 真实 3080 工作台：通过原“我的看板→更多→分享”入口加载新弹窗，复用已有服务器链接，真实服务端预检通过，Tooltip 正常。分享页未观察到脚本错误。部分既有看板缩略图显示独立的数据绘图错误，不在本次修改范围。
- 隔离测试页曾在测试服务重启期间出现统计轮询空响应错误，已修复测试工具；新测试页面错误日志为空，不属于生产分享请求。

## 能力边界 / 未进行的外部操作

- 现有接收人是单选；没有多人部分成功接口，因此没有虚构群发。
- 现有人员搜索要求本机飞书 CLI 通讯录授权，单独填写应用凭据不能代替该授权。
- 本机实时服务仅保存令牌摘要，无法在刷新页面后恢复完整 URL。当前页内可复用，重新打开能还原的服务器/快照链接直接复用；不可还原的记录明确提示并保留撤销入口，未改为存储明文令牌。
- 没有独立发送状态查询接口；使用原有持久化幂等编号安全重试，超出原去重窗口仍由原服务拒绝；不声称消息已读或自动授权。
- 服务器预检确认登记的版本与链接及卡片内容，不冒充接收人的 Jupyter 登录/网络连通性验证。
- 没有给真实同事发送消息、生成新的生产分享链接或撤销已有生产链接。5 张交付截图来自实际组件运行的隔离接口响应，不是飞书实际送达证明。
