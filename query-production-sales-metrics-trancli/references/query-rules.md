# 查询规则

## 时间规则

- 当前可用数据年份：`2024`、`2025`
- 默认不支持 2026，除非用户明确确认替代口径。

## 追问确认规则

当请求包含以下时间表达时，查询前必须先向用户确认：
- `本月`
- `今年`
- `最近`
- `最新`
- `2026`
- `26年`
- 任何可能包含 2026 的时间范围

建议确认话术：

```text
当前数据源仅包含 2024 年和 2025 年数据。你提到的时间范围可能落在 2026 年，请确认你是要查 2025 年最近可用月份、2025 年同期，还是仅确认当前暂无 2026 年数据。
```

## 指标映射规则

- 匹配指标时，必须同时结合：
  - 指标名
  - 字段名
  - 字段解释
  - 指标定义
- 只能使用 `metric-catalog.json` 里已定义的指标。
- 当请求涉及同期、环期等分析时，使用指标里声明的相关字段。

## 维度规则

- 维度只能从 `dimension-catalog.json` 里匹配。
- 维度字段只用于分组或筛选。
- 不要把维度字段当作指标值。

## SQL 规则

- 正式取数前，必须先调用一次 DDL 作为前置验证。
- 只有 DDL 返回成功、目标表存在、所需字段存在时，才继续生成 SQL。
- 如果 DDL 校验失败，停止查询并返回明确原因。
- 只能查询实时 DDL 中存在的字段。
- 返回列优先使用明确别名。
- 只有当指标定义要求聚合时，才做聚合。
- 对于复合指标，严格按已存公式执行。
- 如果复合指标缺少必要字段，要明确说明当前数据源不能直接查询该指标。

## 返回规则

- 返回查询结果，或者明确说明为什么当前不支持。
- 回复必须围绕查询数据本身。
- 不要切换成看板设计、页面生成或 HTML 布局任务。
